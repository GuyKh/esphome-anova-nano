# ESPHome Anova Nano

ESPHome external component for the **Anova Nano** sous vide cooker over Bluetooth LE, using an ESP32 as a BLE proxy.

The protocol is a port of [pyanova-nano](https://github.com/filmkorn/pyanova-nano). Byte-level parity with the reference is enforced in CI: the test vectors in `tests/golden_vectors.h` are generated by running pyanova-nano's own code, and CI fails if they drift.

## Features

| Entity | Platform | Source (pyanova-nano) |
|---|---|---|
| Climate (mode heat/off, target, current temp) | `climate` | `start()` / `stop()` / `set_target_temperature()` / `get_target_temperature()` / `get_sensor_values().water_temp` |
| Water, heater, triac, internal temperature | `sensor` | `get_sensor_values()` |
| Target temperature | `sensor` | `get_target_temperature()` |
| Motor speed | `sensor` | `get_sensor_values().motor_speed` |
| Timer remaining (min) | `sensor` | `get_timer()` |
| Running | `binary_sensor` | `get_status()` (motor speed ≠ 0) |
| Water low, water leak | `binary_sensor` | `get_sensor_values()` |
| Cooking timer (set) | `number` | `set_timer()` |
| Display unit C/F (set) | `select` | `set_unit()` / `get_unit()` |
| Firmware version / commit | `text_sensor` | `GET_FIRMWARE_INFO` |
| Device info (raw), reported unit | `text_sensor` | `get_device_info()` / `get_unit()` |

All temperatures are published in °C. If the cooker is set to °F, readings are converted, and setpoints are converted back before being sent. The cooker's own display unit is never changed unless you use the `unit` select.

## Requirements

- An ESP32 with BLE (any variant except the ESP32-S2), ESP-IDF framework recommended
- ESPHome: built and tested against 2026.9. Older releases may lack the APIs used here (climate feature flags, index-based `select` control).
- Your cooker's BLE MAC address. It advertises as `Nano`. Find it in the `esp32_ble_tracker` logs or with `bluetoothctl scan on`.

The Nano accepts a single BLE connection. Close the Anova app (or disable Bluetooth on the phone) while the ESP32 is connected.

## Usage

```yaml
external_components:
  - source: github://GuyKh/esphome-anova-nano
    components: [anova_nano]

esp32_ble_tracker:

ble_client:
  - mac_address: "AA:BB:CC:DD:EE:FF"
    id: anova_ble

anova_nano:
  id: anova
  ble_client_id: anova_ble
  update_interval: 30s   # default, same as PyAnova

climate:
  - platform: anova_nano
    name: "Sous vide"
```

Every other entity is optional. See [`example/anova_nano.yaml`](example/anova_nano.yaml) for the full set.

### Configuration

**`anova_nano`** (hub)
- `ble_client_id` (**required**): the `ble_client` connected to the cooker.
- `update_interval` (optional, default `30s`): how often to poll units, sensors, setpoint and timer.
- `id` (optional): needed if you have more than one cooker. Entities then take `anova_nano_id`.

**`sensor`** keys: `water_temperature`, `target_temperature`, `heater_temperature`, `triac_temperature`, `internal_temperature`, `motor_speed`, `timer`.

**`binary_sensor`** keys: `running`, `water_low`, `water_leak`.

**`text_sensor`** keys: `firmware_version`, `firmware_commit`, `device_info`, `unit`.

**`number`** key: `timer` (minutes, 0–5999).

**`select`** key: `unit` (options `C`, `F`).

## How it works

- **Wire format:** `COBS([0x00 domain, message type, protobuf payload]) + 0x00`. It is written to `0e140001-…` without response; responses arrive as notifications on `0e140002-…`.
- **Command handling:** one command is in flight at a time, with a 10 s response timeout (PyAnova's `_command_lock` / `_READ_DATA_TIMEOUT_SEC`). Notifications are reassembled across chunks.
- **Sensor list:** decoded positionally, exactly like `get_sensor_values()`: water, heater, triac, *(unused)*, internal, water low, water leak, motor speed. Each value is scaled by its own unit.
- **Setpoint encoding:** `round(t × 10)` with round-half-to-even, matching Python's `round()`. So 60.25 °C becomes `602`, not `603`.
- **proto3 defaults:** zero-valued fields are omitted on the wire and decode as 0.

## Development

```bash
make -C tests                       # protocol unit tests (host, ASan/UBSan)
pip install "pyanova-nano==0.3.5"
make -C tests golden                # regenerate golden vectors from the reference
esphome compile tests/build-full.yaml
```

When pyanova-nano changes, bump the pinned version in `.github/workflows/ci.yml`, regenerate the vectors, and review the diff.
